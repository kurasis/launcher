# 12 — User experience and accessibility

## Design principles

The product language is rooms, worlds, friends, host and connection. Hide implementation details unless they explain a decision or error. Use centralized design tokens and reusable accessible React components. Russian and English ship together; dates, units, plural forms and long text are localized.

## Required screens

| Screen | Required content/actions |
| --- | --- |
| Rooms | Search, joined/owned rooms, host availability, last session, create/join |
| Create room | Name, new/imported world, qualified game build, host resource plan, privacy, first-use terms |
| Room details | World cover, members, role, host, selected build, start/join, invites, history |
| Invitation preview | Inviter, minimal room details, required content, expiry, accept/request approval |
| Join preparation | Exact downloads, disk needs, consent, each readiness stage, cancel/retry |
| Hosting panel | Players, process health, route summaries, save/stop, resource plan and redacted logs |
| World recovery | Snapshots, local/remote custody, verification state, restore preview, export |
| Device settings | Registered devices, assigned rooms, revocation, remote-host controls when enabled |
| Diagnostics | Distinguish client FPS, server health and network failures; export preview |

Room cards must distinguish sleeping/offline host, unavailable control service, unsupported build and full room. No generic infinite spinner. Display last observation time when presence is stale.

## Join state machine

`preview -> authorization -> plan -> consent -> download -> verify -> host_wait -> listener_ready -> game_start -> client_connect -> admission -> identity_binding -> playing`.

The local listener is armed before client launch, but a short-lived ticket is requested only when the client actually attempts gameplay. A player is not shown as admitted until the pre-play identity hook completes. Slow Java startup, tunnel establishment and identity verification have separate progress/errors.
Any stage can enter a specific recoverable failure, cancellation or permission-denied result. Persist operation ID so reopening the UI resumes the displayed state. Cancellation before spawn prevents spawn. After game spawn, use a separate explicit leave/stop action; do not kill it because a progress dialog closed.

Each state shows the current action, meaningful progress, cancelability and what data will be kept. Preserve verified downloads on cancellation. Differentiate host startup from local downloading and actual game loading.

## Closing and reopening

Normal UI close detaches only the UI. During hosting, a one-time explanatory preference states that the server continues in the background. Tray/status integration is helpful but cannot be the sole control surface on platforms without a reliable tray. Reopening the launcher must reconnect to the existing agent.

Explicit Quit while active offers `Keep hosting in background`, `Save and stop hosting`, and `Cancel`. If only a guest tunnel is active, explain that stopping the agent disconnects the game. Device shutdown/sleep cannot be hidden behind a promise of permanent availability; prevent idle sleep only with an explicit user setting and OS-supported mechanism.

## Destructive actions

Restore, force stop, owner transfer, world deletion and new executable-content installation show a concrete impact preview. Ordinary reconnect, safe retry and verified cache reuse do not prompt repeatedly. A previously accepted exact executable generation need not ask again; a changed digest or publisher policy does.

## Accessibility

Complete keyboard operation, visible focus, labelled controls, screen-reader status announcements, contrast, text scaling and reduced-motion support. Do not encode connection status only with color. Use virtualization for large logs; never flood accessibility announcements with every log line.

## Advanced features

Show remote host, migration, cloud and voice only when the corresponding milestone and backend capability are active. Disabled future features must not masquerade as completed controls. Keep account/room authority and host computer ownership understandable to users.

Privacy policy changes explain that active connections may need to reconnect using new endpoint contexts; stricter policy does not erase addresses previously disclosed. During maintenance, room cards show snapshot/restore/reconciliation instead of merely offline. A failed backend/local commit gives an explicit recovery state and disables Join until reconciled.

## Additional failure and recovery states

Show cancelling-start until a racing spawned child has actually stopped; waiting-for-player-cleanup while a previous game binding is closing; uninitialized-world before first publication; and recovery-required when a maintenance worker expired. Provide query/reconcile actions tied to the original operation, never a blind new restore button. Restore preview names the snapshot's required build and any player-mapping issue. Export preview distinguishes private preparation from disclosure to the selected destination. Changing route policy on a running room offers stop first and explains reconnect/privacy impact.
